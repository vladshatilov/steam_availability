# netmon: кто виноват, когда отваливается Steam или интернет

Скрипт для Windows, который показывает, на каком участке пути возникает проблема:

- ваш компьютер и роутер;
- провайдер;
- зарубежный канал / РКН (ТСПУ);
- Cloudflare (в том числе типичное замедление «после 16 КБ»);
- сам Steam: магазин/сайт или серверы подключения клиента.

Скрипт проверяет все участки параллельно (по умолчанию каждые 15 секунд) и пишет результат в журнал.
По журналу потом видно, когда и что именно ломалось. С ним проще разговаривать с провайдером:
вместо «у меня всё отваливается» есть время, длительность и участок, на котором был сбой.

## Требования

- Windows 10/11.
- PowerShell 7 (`pwsh`). Установка: `winget install Microsoft.PowerShell`.
  Встроенный Windows PowerShell 5.1 не подойдёт.
- Права администратора не нужны.

## Установка

1. Скачайте репозиторий (Code → Download ZIP) и распакуйте в удобную папку, например `C:\netmon`.
   Можно и через `git clone https://github.com/vladshatilov/steam_availability.git`.
2. Если Windows блокирует скачанные скрипты, один раз выполните в PowerShell в этой папке:
   `Get-ChildItem | Unblock-File`.
3. Для запуска с рабочего стола: правый клик по `netmon.bat` → «Отправить» → «Рабочий стол (создать ярлык)».
   Нужен именно ярлык, а не копия: `.bat` ищет `netmon.ps1` рядом с собой.

## Файлы

| Файл | Что это |
|---|---|
| `netmon.ps1` | сам скрипт |
| `netmon.bat` | запуск двойным кликом, открывает меню |
| `data\` | всё, что собирает скрипт (создаётся автоматически рядом со скриптом) |

## Меню

Двойной клик по `netmon.bat` (или его ярлыку) открывает меню:

| № | Пункт | Время | Что делает |
|---|---|---|---|
| 1 | Быстрая проверка | ~1 мин | 3 цикла проверок и итоговая таблица: что работает, что нет |
| 2 | Снапшот сети | ~1.5 мин | сохраняет конфиг маршрутов и трассировки (см. «Снапшот») |
| 3 | Снапшот + pathping | ~5–7 мин | то же + pathping: процент потерь на каждом узле маршрута |
| 4 | Мониторинг до остановки | сколько нужно | останавливается клавишей **Q**, **Esc** или **Ctrl+C**, в конце выводит отчёт |
| 5 | Мониторинг на N минут | N мин | сам останавливается и выводит отчёт |
| 6 | Отчёт за последние N часов | сразу | что происходило за период (см. «Отчёт») |
| 7 | Сравнить снапшоты | сразу | что поменялось в маршрутах между двумя последними снапшотами |
| 8 | Открыть папку с данными | | |
| 9 | Автозапуск при входе в Windows | | включает или выключает (см. «Постоянный мониторинг») |
| 10 | Очистить старые данные | сразу | удаляет данные старше срока хранения (см. «Хранение данных») |

После каждого пункта окно ждёт Enter и возвращается в меню, поэтому результат не пропадает.

## Запуск из командной строки

Все пункты меню доступны и без него:

```powershell
pwsh -File netmon.ps1 -Mode Check                        # быстрая проверка
pwsh -File netmon.ps1 -Mode Snapshot                     # снапшот
pwsh -File netmon.ps1 -Mode Snapshot -Deep               # снапшот + pathping
pwsh -File netmon.ps1 -Mode Monitor                      # мониторинг до остановки
pwsh -File netmon.ps1 -Mode Monitor -DurationMin 60      # мониторинг на 60 минут
pwsh -File netmon.ps1 -Mode Monitor -IntervalSec 30      # проверять раз в 30 секунд вместо 15
pwsh -File netmon.ps1 -Mode Report -Hours 24             # отчёт за последние 24 часа
pwsh -File netmon.ps1 -Mode Diff                         # сравнить два последних снапшота
pwsh -File netmon.ps1 -Mode AutostartOn                  # включить автозапуск (AutostartOff - выключить)
pwsh -File netmon.ps1 -Mode Cleanup                      # удалить старые данные
```

Если скрипт запущен в собственном окне (через Win+R, ярлык или автозапуск), в конце он ждёт Enter,
чтобы окно не закрылось раньше, чем вы прочтёте результат. Из уже открытого терминала он просто
завершается. Ключ `-NoPause` отключает ожидание (нужен для Планировщика заданий).

## Что проверяется

| Участок | Как |
|---|---|
| Сетевая карта | включён ли адаптер, есть ли маршрут в интернет |
| Роутер | ping шлюза |
| Провайдер | ping первого узла провайдера за роутером. Узел находится автоматически через tracert |
| DNS | запрос к DNS, который использует Windows, напрямую, мимо кэша (ya.ru, адреса Steam) |
| РФ | ping серверов Яндекса 77.88.8.8 / 77.88.8.1 + открытие ya.ru и vk.com |
| Зарубеж | ping 1.1.1.1, 8.8.8.8, 9.9.9.9 + открытие google и github |
| Cloudflare | открытие маленькой страницы + скачивание 256 КБ. Если маленькая страница открывается, а 256 КБ не скачиваются за 6 секунд, это типичное замедление ТСПУ (соединение «замерзает» после ~16 КБ) |
| Steam: сайт | store.steampowered.com, api.steampowered.com, steamcommunity.com |
| Steam: подключение клиента | TCP-соединение с 5 серверами подключения (CM). Список берётся из официального API Steam при каждом запуске. Именно эти серверы нужны клиенту, чтобы он не уходил в «нет соединения» |

Скрипт проверяет напрямую, мимо системного прокси. Каждый раз открывается новое соединение, чтобы
вмешательство ТСПУ было видно.

Не проверяется: игровой трафик Steam по UDP (матчи, голос). Скрипт проверяет только подключение
клиента и сайт.

## Вердикты

Каждый цикл получает один вердикт. Проблемы с Cloudflare и Steam могут совмещаться через `+`,
например `CF_THROTTLE+STEAM_CM`.

| Вердикт | Что значит | Кто виноват |
|---|---|---|
| `OK` | всё работает | — |
| `LINK_DOWN` | пропал линк на сетевой карте или маршрут в интернет | кабель, порт роутера, драйвер, перезагрузка роутера |
| `LAN_ROUTER` | линк есть, роутер не отвечает | роутер |
| `PROVIDER_EDGE` | роутер жив, не отвечает даже первый узел провайдера | линия / подключение роутера к провайдеру / оборудование провайдера |
| `PROVIDER_UPSTREAM` | роутер и первый узел провайдера отвечают, но ни РФ, ни зарубеж не доступны | сеть провайдера дальше первого узла (при этом ваша сессия цела) |
| `PROVIDER` | то же, но первый узел провайдера не отвечает на ping, уточнить нельзя | провайдер |
| `DNS` | IP-адреса пингуются, имена не резолвятся | DNS роутера / провайдера |
| `INTL_DOWN` | РФ работает, зарубеж нет | внешний канал провайдера или ТСПУ/РКН |
| `CF_DOWN` | зарубеж работает, Cloudflare нет | блокировка Cloudflare |
| `CF_THROTTLE` | Cloudflare отвечает, но не качает | замедление ТСПУ |
| `STEAM_ALL` | зарубеж работает, Steam целиком нет | Steam лежит или блокировка |
| `STEAM_CM` | серверы подключения Steam недоступны | Steam / блокировка CM. Клиент пишет «нет соединения» |
| `STEAM_WEB` | магазин/community/API не открываются, CM работают | Steam web / блокировка |
| `LOSS` | часть проверок не прошла | единичные потери, обычно не страшно, если не повторяется подолгу |
| `NO_DATA` | в отчёте: монитор не работал | сон ПК, закрытое окно |

В деталях ошибок встречаются коды: `timeout` — нет ответа, `reset` — соединение сброшено
(частый признак DPI/ТСПУ), `refused` — порт закрыт, `tls` — ошибка шифрования,
`dns` — имя не резолвится.

## Отчёт

Отчёт собирает всё, что мониторинг записал за выбранный период. В меню это пункт 6: скрипт спросит,
за сколько последних часов показать (по умолчанию 24). Из командной строки:

```powershell
pwsh -File netmon.ps1 -Mode Report                       # за последние 7 дней (по умолчанию)
pwsh -File netmon.ps1 -Mode Report -Hours 3              # за последние 3 часа
pwsh -File netmon.ps1 -Mode Report -Hours 48             # за последние двое суток
pwsh -File netmon.ps1 -Mode Report -Since "2026-11-24 18:00"   # начиная с конкретного момента
```

Что в отчёте:

1. **Распределение вердиктов**: какую долю времени было `OK`, а какую — каждый тип проблемы.
2. **Инциденты**: список сбоев с началом, концом, длительностью, вердиктом и примером ошибок,
   например `11-24 21:14:05 - 21:16:35  00:02:30  PROVIDER_UPSTREAM ...`. Промежутки, когда
   мониторинг не работал, помечены `NO_DATA`.
3. **События монитора**: старт/стоп, пропадание линка, смена внешнего IP.
4. **События Windows**: когда Windows фиксировала подключение и отключение сети.
5. **Итоговые таблицы** «что работает, что нет»: по последнему циклу и по всему периоду.

Отчёт строится только по данным мониторинга (пункты 1, 4, 5 или автозапуск). Если мониторинг в этот
период не работал, отчёт будет пустым.

## Как проверить слова провайдера «сессия не обрывалась»

- **`PROVIDER_UPSTREAM`**: роутер и первый узел провайдера отвечают, а интернета нет. Значит,
  связь с провайдером цела, а ломается его сеть дальше. Провайдер прав, что сессия не обрывалась,
  но проблема всё равно на его стороне.
- **`PROVIDER_EDGE`**: не отвечает даже первый узел провайдера, проблема на линии или в подключении
  роутера.
- **`LINK_DOWN` / `LAN_ROUTER`**: проблема у вас (кабель, роутер). Отчёт дополнительно показывает
  события Windows о подключении и отключении сети.
- **Смена внешнего IP** проверяется каждые ~5 минут и после каждого восстановления связи, изменения
  пишутся в `events.log`. Если первый узел провайдера имеет адрес вида `100.64.x.x`–`100.127.x.x`,
  у вас общий внешний IP на многих абонентов (CGNAT). Тогда смена IP не обязательно означает обрыв
  вашей сессии.
- Самое точное доказательство обрыва сессии — журнал роутера и время непрерывной работы
  WAN-подключения в его веб-интерфейсе. Сравните их со временем инцидентов из отчёта.

## Постоянный мониторинг (автозапуск при входе в Windows)

Редкие сбои проще всего поймать, если мониторинг работает постоянно.

**Включить**: пункт 9 в меню или `pwsh -File netmon.ps1 -Mode AutostartOn`.
Скрипт кладёт ярлык `netmon-monitor.lnk` в папку автозагрузки текущего пользователя
(`Win+R` → `shell:startup`). При каждом входе в Windows мониторинг запускается в свёрнутом окне на
панели задач.

- Если сеть при входе ещё не поднялась, скрипт ждёт её и стартует сам.
- Посмотреть текущее состояние: развернуть окно.
- Остановить: развернуть окно и нажать **Q**. Скрипт покажет итоговый отчёт за сеанс и закроет окно
  по Enter.
- Отчёт за любой период: пункт 6 меню, можно параллельно с работающим мониторингом.

**Выключить**: снова пункт 9 или `pwsh -File netmon.ps1 -Mode AutostartOff`
(или просто удалить ярлык из `shell:startup`).

Если папку со скриптом перенесли, автозапуск нужно выключить и включить заново: в ярлыке записан путь.

**Вариант без окна** (через Планировщик заданий, может потребовать запуска консоли от администратора):

```
schtasks /create /tn netmon /sc onlogon /tr "pwsh -NoProfile -WindowStyle Hidden -File C:\путь\к\netmon.ps1 -Mode Monitor -NoPause"
schtasks /delete /tn netmon /f
```

В этом варианте остановить мониторинг можно только через Диспетчер задач (процесс `pwsh`).

Не запускайте два мониторинга одновременно (автозапуск + пункт 4): оба будут писать в одни и те же
файлы.

## Хранение данных

По умолчанию данные хранятся 14 дней. Мониторинг сам чистит старое при старте и раз в сутки.
Удаляется:

- файлы `cycles_*.csv` старше срока;
- трассировки в `traces\` старше срока;
- снапшоты старше срока, кроме трёх последних (они нужны для сравнения маршрутов);
- строки `events.log` старше срока.

Объём при интервале 15 секунд — примерно 2–3 МБ в сутки, то есть около 40 МБ за 14 дней.

Изменить срок: параметр `RetentionDays` в блоке `$Cfg` в начале `netmon.ps1` (`0` — не удалять
ничего) или ключ `-RetentionDays N` при запуске. Почистить вручную: пункт 10 меню или
`-Mode Cleanup`.

## Что лежит в `data\`

| Путь | Содержимое |
|---|---|
| `cycles_ГГГГММДД.csv` | одна строка на цикл: результат каждой группы проверок (`успешно/всего` и средняя задержка), вердикт, ошибки. Открывается в Excel |
| `events.log` | старт/стоп, смена вердикта, пропадание линка, смена внешнего IP, запущенные трассировки, очистка |
| `traces\` | трассировки, которые скрипт сам запускает в начале каждого сбоя до того, что отвалилось |
| `snapshots\ГГГГММДД_ЧЧММСС\` | снапшоты сети |
| `steam_cm.json` | последний полученный список серверов подключения Steam (на случай, если API Steam недоступен) |

### Снапшот (сохранённый конфиг маршрута)

Сохраняются: `route_print.txt`, `ipconfig_all.txt`, `netipconfiguration.txt`, `adapters.txt`,
`dns_servers.txt`, `mtu.txt`, `winhttp_proxy.txt`, трассировки до Яндекса, 1.1.1.1, 8.8.8.8,
магазина Steam, Cloudflare и сервера подключения Steam (`tracert_*.txt`), с `-Deep` / пунктом 3
ещё `pathping_*.txt`. Сводка (шлюз, DNS, первый узел провайдера, внешний IP) лежит в
`summary.json`. Мониторинг тоже делает снапшот при каждом запуске.

Пункт 7 сравнивает два последних снапшота: какие узлы маршрута поменялись и изменились ли шлюз, DNS,
первый узел провайдера и внешний IP. Удобно сделать снапшот, пока всё работает, и ещё один во время
проблем.

Внимание: в снапшотах есть ваш внешний IP, MAC-адреса и имена сетей. Прежде чем выкладывать их
публично, просмотрите содержимое.

## Настройка

Адреса и параметры проверок задаются в блоке `$Cfg` в начале `netmon.ps1`: какие сайты и IP
проверять, таймаут для Cloudflare 256 КБ, IP первого узла провайдера (если автоопределение
ошибается), как часто проверять внешний IP, срок хранения данных.

## Важно

- Если включён VPN, проверки пойдут через него, а не напрямую. Скрипт предупредит об этом красной
  строкой. Для диагностики провайдера VPN нужно выключить.
- Первый цикл после старта прогревочный и в журнал не пишется: при самом первом запуске HTTP/TLS
  бывают ложные таймауты.
- Если роутер или первый узел провайдера не отвечают на ping, их проверка отключается, о чём скрипт
  пишет при старте.
